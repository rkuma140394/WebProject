01

Why JavaScript Exists

The story of Netscape, Sun, and the ten-day miracle that changed the web.

In the early 1990s, a web page was a static document. It could show text and images, and that was essentially all. There was no way for a page to react to you. If you filled in a form and made a mistake, the page could not tell you on the spot. It had to ship your data all the way to a distant server and wait for the server to send back a reply just to say "that's wrong, try again."

Netscape — makers of the dominant browser of the era — realised the web needed to come alive. It needed to respond instantly, right there in the page. That need is the seed of everything that follows.

The Players

🌐

Netscape

Dominant browser maker (1990s). Wanted the web to "come alive."

☕

Sun Microsystems

Created Java, sold internet servers. Wanted Java in the browser.

🪟

Microsoft

The common enemy. Everyone needed Windows to run software.

Java vs JavaScript

Java (Component)
JavaScript (Glue)
Powerful, professional
Light, simple, forgiving
Ran in sealed applet
Woven into the page itself

Built-in, instant execution

Became the language of the web

The Ten-Day Miracle

Netscape hired Brendan Eich in May 1995. Marketing demanded the new language look like Java to ride Java's popularity. Eich built the prototype in roughly ten days. The name "JavaScript" was pure marketing — the two languages are as related as "car" and "carpet."

Why Not C++?

1
Too heavy — 1995 PCs had 4-8 MB RAM, 200-400 MB hard disks
2
Security nightmare — unrestricted file access, raw memory pointers, system() calls
3
Wrong audience — web designers, not kernel developers
4
No garbage collection — manual memory management error-prone

Modern Parallel: WebAssembly

WebAssembly lets C++/Rust run in browser at near-native speed. But just like Java in 1995, it cannot touch the page. It must call out to JavaScript for DOM manipulation. The "glue" role of JavaScript never changed.

💡
Takeaway: JavaScript owns the browser tab. It won by being woven into the page, already there, ready to run.

Variables & Scope

const, let, var — and why the choice matters more than you think.

Data Types

Primitives vs Objects, value vs reference, and the typeof quirks.

Computer memory is just bytes. 01001000 could be the number 72, the character 'H', a memory address, or a boolean true. Data types tell the computer how many bytes to use and what operations make sense.

JavaScript is dynamically typed: variables hold any type, figured out at runtime.

Object Type — Mutable, Stored by Reference

Includes: {}, [], function, Date, RegExp, Map, Set

Value vs Reference

value-vs-reference.js 
// Primitives — copied by VALUE
let a = 10;
let b = a;     // 10 is copied into b
b = 20;
console.log(a); // 10 — unchanged

// Objects — copied by REFERENCE
let obj1 = { value: 10 };
let obj2 = obj1;  // Memory address copied
obj2.value = 20;
console.log(obj1.value); // 20 — same object in memory!

Control Flow

if/else, for, while, do-while — directing the execution path.

Control flow determines the order in which statements execute. Use if / else for branching, and loops for repetition.

If / Else Chain

Evaluated top-to-bottom. The first true condition wins.

if-else.js 
let score = 85;

if (score >= 90) {
  grade = 'A';
} else if (score >= 80) {
  grade = 'B';        // This runs
} else if (score >= 70) {
  grade = 'C';        // Skipped
} else {
  grade = 'F';
}

Numbers & Math

IEEE-754 floats, the 0.1 + 0.2 bug, and the Math object.

JavaScript uses IEEE-754 double-precision floats for the number type. There is no separate integer type — both 42 and 3.14 are the same type.

The Floating-Point Bug

float-bug.js 
0.1 + 0.2 === 0.3     // false
0.1 + 0.2             // 0.30000000000000004
▶ Run

Why? 0.1, 0.2, and 0.3 have infinite repeating representations in binary. The computer rounds them to fit 64 bits. Tiny errors accumulate.

⚠️
Solutions: Financial calculations use integers (store money in cents). Display with price.toFixed(2). Comparison checks "close enough" with Number.EPSILON.

09

Comparison Deep Dive

=== vs ==, relational traps, and object equality.

Use === and !== for predictable comparisons. Loose equality (==) performs complex coercion rules and is a common source of bugs.

Strict Equality (===) — Simple Rules

  1. 1 Types different? → false
  2. 2 Same type? → Compare values
  3. 3 Objects? → Same memory reference only
  4. 4 NaN === NaN → false (always)

Loose Equality (==) — Complex Rules

Scenario
Result
Same types
Behaves like ===
null == undefined
true
String vs Number
Convert string to number
Boolean involved
Convert boolean to number (true→1, false→0)
Object vs Primitive
Convert object to primitive first

Relational Operators (< > <= >=)

Scenario
Behavior
Both strings
Dictionary (lexicographical) comparison
Anything else
Convert both to numbers, then compare
undefined involved
Becomes NaN → result always false

Famous Trap

trap.js

// (3 > 2) → true
// true > 1 → 1 > 1 → false
